# 八阶段分析协议

目录：共同规则；阶段 1 黑盒；2 架构；3 表示；4 机制；5 训练推理；6 追踪；7 创新证据；8 理解验证；最终验收。局部模式只读对应部分。

## 共同规则：来源、解释与未知

登记来源 ID、文件/URL、版本、正文/补充/辅助身份、已读范围及缺页。正文事实用 `[论文明确]`，作者 Appendix/Supplement 用 `[补充材料]`（注明版本）；合理推导用 `[推断]` 并列前提；构造值用 `[教学示例]`。辅助资料在标签之外写独立来源身份，不能因官方而自动当本文正文。未确定事实写“原文未说明”，并记需要什么证据。

定位采用来源 ID + PDF 页码 + 章节/图表/公式；区分 PDF 页序与印刷页码。图片缺失/公式提取损坏回查 PDF，不可读则标记。正文与表格、不同版本冲突并列，不静默修正。

复杂概念按例子、定义、数据结构、操作、公式、原因解释。先给批次/序列/特征等轴意义；符号维度可以未知，但上下游必须一致。每个公式变量解释含义、形状、范围、单位、来源/是否学习和下游角色。无适用单位写无量纲，无法判断写未知。

## 阶段 1：Black-Box Interface Analysis

本阶段暂不解释内部模型。给研究问题、现有方法的具体失败和目标场景。

列系统输入输出的数据类型、字段、长度/时间结构、维度和单位；输出如何消费，成功需要什么。区分直接输出的数值/离散对象与渲染后的动作/图像。无固定长度时用变量，不猜常量。

验收：能描述一个合法输入输出，区分格式正确和语义正确。

## 阶段 2：System Architecture & Module Contracts

用 Method 与架构图交叉梳理完整数据流，画 Mermaid 或等价图，包括离线资产、训练、推理和后处理。不要强加不存在的分支。

每个核心模块列 Module、Input（类型/形状/来源）、Representation、Operation、Output（类型/形状/语义）、Purpose、Consumer（如何消费）、Evidence。复杂模块递归展开到明确操作或证据边界。标记固定规则/可学习/冻结模型/外部服务。

验收：相邻接口的类型、轴、语义相容；输出有消费方，离线资产有来源；不把离线训练误画成全部在线依次执行。

## 阶段 3：Data Representation & Transformation

对每次核心转换给输入实例/前形状 → 预处理或计算 → 输出实例/后形状 → 下游用法 → 可逆性/信息保留或丢失 → 设计理由/证据。

按实际情况解释归一化、分词、分箱、离散化、量化、Embedding、编码/解码。区分检索向量、token/位置向量、模态与输出表示。

Codebook 须拆开符号类别、整数 ID、码本行、可学习向量、激活向量；说明查表/组合/量化，单码或多码，如何训练及供后续模型使用。离散化给坐标系、公式、阈值、边界开闭、单位；未公布项逐项标未知。

验收：能手算一个小转换，或精确指出缺哪条规则使计算不可行；不能以“被编码”结束。

## 阶段 4：Mechanism-Level Deep Dive

按实际机制选读 paper-archetypes 相应分支。每个机制回答怎么做、为什么需要、保留或限制什么。

先用小例子解释运算，再连接论文公式和真实形状。已知输入不代表 attention mask、聚合、阈值或采样也已知。作者设计动机注明来源；自行比较替代方案标推断，不声称替代方案已被实验排除。

验收：术语落地为数据与运算，概率如何变选择、内部表示如何变最终预测均有交代。

## 阶段 5：Training vs. Inference

分别画训练与推理路径。训练解释数据/标注来源、Ground Truth 构造、划分、可训练/冻结模块、优化参数、每项 Loss 的公式/变量、目标和超参数依据。

推理从新输入开始，列权重/索引/规则依赖、确定性步骤、概率预测、采样、重建与终止。区分教师强制/生成历史、标签/条件、训练随机遮挡/推理缺失字段。

核查泄漏：划分单位、近重复/主体/时间关系、索引和预处理拟合范围、测试标注是否进入模型/提示。未交代写“无法据现有资料排除”，不自行判无泄漏。Human/oracle 条件单列。

验收：推理不需要本来未知的标签；训练信号可追到来源。

## 阶段 6：End-to-End Concrete Trace

优先选论文真实输入；无公开案例时用明确教学输入。Raw Input → 所有核心中间对象 → Final Output，节点各列内容、类型/形状、上一阶段的计算规则、下游使用字段与来源标签。

真实输入不会让构造的中间值变真实日志；人工补充逐段标教学示例，未知真实数值保留符号。用小规模数值说明当前机制需要的查表、加权、概率、分箱或解码，并检查形状/运算一致。未公开的排序/格式/阈值不能为讲故事而补成事实。

验收：不跳过关键接口；不能计算时写缺失规则，展示后续结构而不伪造结果。

## 阶段 7：Innovation & Experimental Evidence

建立“既有限制 → 提出改变 → 预期收益 → 实验 → 支持结论”链。识别表示、结构、训练目标、推理、系统组合、数据集或评估贡献；复用组件不自动算独立创新。

说明数据来源/构建/划分、基线检验什么、指标计算对象/方向/单位、关键数值、重复次数/不确定性、消融改变和控制什么、失败和局限。

区分作者声称、表格支持、尚未验证的因果解释。主动检查方向冲突、oracle 优势、评估器偏好、同时改变多变量、选参是否使用测试集。对用于支撑结论的计数、总时长、倍数、百分比做量纲与算术一致性复核；口径缺失时保留冲突，不替作者猜修正值。性能好不证明每模块必要；经验最优不等于普遍保证。

验收：每创新有实验或标未验证，不扩大结论范围。

## 阶段 8：Synthesis & Understanding Verification

汇总一句话贡献、精确 I/O、完整数据流、表示/维度、机制、训练推理区别、最多三项贡献及证据、局限/未知。

给五道机制题，覆盖数据转换、条件/路径变化、设计权衡和证据边界，不暗示未经证明前提。附独立折叠答案要点，区分原文与推导，便于自测。

## 最终验收

- 数据链字段、形状、语义、单位相容，尤其概率 → 离散选择 → 表示组合 → 输出。
- 公式与小例子运算一致，不能核验的值明确标注。
- 关键陈述标签/来源与版本匹配；未知没有在后文悄悄变已知。
- 训练/oracle 信息不进入普通推理，实验结论与理解题不超证据。
- 资料不足可诚实披露，概括代替机制不通过；full 只有八阶段全完成才称完整报告。
